# 宿主交换空间设置、低内存保护与游戏触屏指南（v0.1.6+）

**简体中文** · [English](en/low-memory.md) · [实机验收记录](06_验收记录.md) · [返回主页](../README.zh-CN.md)

## 1. 功能背景与物理内存边界

在 4 GB 树莓派 4 宿主上，宿主 Android 系统、Google 服务、图形管线与所有虹膜空间实例共同分享同一块物理内存（实测可用物理 RAM 约 `3.69 GiB`）。实例设置中的 `2048 MiB` 是**内存使用上限（Ceiling）**，而非凭空增加的物理内存。

**`v0.1.6 / e27`** 新增宿主级**交换空间（Swap）**设置：通过将暂时不活跃的内存页换出到磁盘，有效缓解大型应用或双开时的物理内存压力，但会伴随一定的磁盘读写延迟与空间占用。**交换空间不能等同于物理 RAM，也不承诺所有大型游戏或双开高负载场景均能流畅运行。**

## 2. 在 App 内配置交换空间与游戏触屏

1. **先停止所有实例**：
   在更改交换空间容量或关闭前，必须先在管理页**正常停止所有虹膜空间实例**（无需重置实例、无需重新导入 ROM、也无需清除 Google 或游戏数据）。
2. **选择共享容量与开机自动恢复**：
   - 在首页或实例列表顶部点击 **“交换空间”**，可选择 **关闭交换空间 / `1 GiB` / `2 GiB` / `4 GiB`**（此为所有实例共享的宿主级 Swap，独立于各实例自己的内存上限）。
   - 如需宿主重启后自动生效，勾选 **“重启后自动恢复（宿主 Magisk）”**，然后点击 **“应用交换空间设置”**。
   - 等待设置完成后，核对页面上方显示的 **已设置 / 已启用 / 已用** 容量，以及 **宿主可用内存 / 磁盘可用 / 文件占用**（可随时点击 **“刷新状态”** 重新读取实时内核数值）。
3. **启动实例与切换游戏触屏模式**：
   - 返回实例列表启动目标实例，待状态显示“桌面已就绪”后点击“进入”。
   - **Unity 游戏触屏提示**：运行《愤怒的小鸟 2》等 Unity 游戏时，请点击全屏顶部工具栏将输入模式切换为 **“输入：触屏”**（默认鼠标指针模式可能无法触发部分游戏按钮或拉动弹弓）。

> [!NOTE]
> **安全停用与拒绝保护**：选择“关闭交换空间”会安全停用本项目的交换文件并移除专属的开机恢复脚本，绝不删除实例数据。若当前仍有实例在运行、文件归属异常、磁盘余量不足（创建时要求除交换文件外至少保留 **2 GiB 磁盘余量**）或物理内存不足以安全换回页面（停用前要求保留至少 **512 MiB 物理内存余量**），系统将直接拒绝操作并提示具体原因——绝不会擅自强停实例、冻结宿主 Google 服务或降低内存保护阈值。

## 3. 开机自动恢复、文件复用与彻底卸载

- **开机自动恢复原理（依赖宿主 Magisk）**：
  勾选自动恢复后，引擎会在 `/data/adb/service.d/irisbox-swap.sh` 安装一份归属本项目的启动脚本。树莓派重启时，该脚本仅核验并启用已保存的交换文件，**不会自动启动任何实例，不修改宿主 `fstab` 或系统分区，且遇到同名非本项目的脚本时会安全拒绝覆盖**。若未勾选自动恢复，宿主重启后交换空间默认停用，需打开 App 重新应用。
- **交换文件保留与快速复用**：
  关闭交换空间后，底层已分配的交换文件保留在 `/data/irisbox/host/swap/` 下；下次重新选择相同容量时可直接复用原文件与 inode，避免重复执行数 GiB 的磁盘写入。若先后切换过 `1 GiB`、`2 GiB`、`4 GiB` 三种规格，磁盘上最多可能保留合计 **7 GiB** 的交换文件（状态栏中的“文件占用”会如实显示其总和）。**切勿手工删除处于激活状态的交换文件**。
- **彻底卸载前清理要求**：
  仅卸载宿主 APK 不会自动删除 `/data/irisbox` 及开机恢复脚本。准备彻底卸载本项目前，请先在 App“交换空间”页将其设为 **“关闭”** 并取消自动恢复，再按 [构建与维护文档](04_构建与维护.md) 清理本项目目录（切勿删除其他项目目录或停用非本项目的交换设备）。

## 4. 权限隔离与启动准入锁机制

- **严格路径与权限校验**：交换文件固定位于 `/data/irisbox/host/swap/`（目录权限 `0700`，文件权限 `0600`，属主 `root:root`），每次操作均核验文件大小、设备号/inode、硬链接数及维护收据（开机日志位于 `/data/irisbox/host/swap/boot.log`，保持私有不公开），**绝不接受 ROM 包或 UI 传入任意文件路径**。当存在未完成的引擎升级（`engine-upgrade.pending`）时，开机脚本会自动跳过恢复。
- **与实例启动共享互斥锁**：交换空间变更与实例启动共用同一把排他/共享文件锁，防止一边启动实例一边停用或切换交换空间。
- **物理内存准入检查保持不变**：宿主与实例的 `swappiness`、实例内存上限及 512 MiB 宿主低内存保护均保持原值；实例启动前的准入检查仍以宿主**物理 `MemAvailable`** 为依据，**不会把磁盘交换空间直接折算为物理可用 RAM**，因此开启 4 GiB 交换空间并不意味着可以无限制调大单实例内存预算。

## 5. 双游戏同屏与《愤怒的小鸟 2》实测复现指南

2026-10-27 实测表明，在 4 GB 树莓派宿主启用 **2 GiB 交换空间**后，`2048 MiB` 实例中的《愤怒的小鸟 2》（`26.7.1`）可顺利进入教程关卡，完成拉弓发射、击碎目标与 Red 技能交互（关闭实例 Root 时教程首段得分 `93,382`，恢复实例 Magisk 后得分 `102,356` 并在双开测试中以 **`203,332 分`** 完成教程结算；期间宿主 `MemAvailable` 保持在 `1.2`～`1.3 GiB`，Swap 已用约 `1.1 GiB`，实例 `OOM-kill` 为 `0`）。

### 双游戏同屏推荐复现顺序
1. **按序启动桌面**：在启用 **2 GiB 宿主交换空间**后，**先启动 `2048 MiB` 的实例 2 并等待桌面就绪，再启动 `1024 MiB` 的实例 1**；待两个实例桌面均就绪后，再分别打开《愤怒的小鸟 2》与《部落冲突》（若先在第一个实例中启动大型游戏占满物理内存，第二个实例启动时可能会被物理内存准入保护正常拒绝）。
2. **教程瞄准提示**：在《愤怒的小鸟 2》新手教程中，若拉弓角度偏离引导线，游戏会显示**红色叉号**并拒绝释放发射；只需在“输入：触屏”模式下拖动对齐**绿色引导轨迹**后松开即可正常发射（并非触屏输入链路故障）。
3. **验收边界**：实机截图与数据仅证明上述教程交互范围通过，不代表长期对战、充值支付、后续全部关卡或稳定帧率承诺；Google Play 下载与设备认证仍为两项独立结果（见 [Google 商店恢复与认证说明](10_Google商店恢复与认证说明.md)）。
