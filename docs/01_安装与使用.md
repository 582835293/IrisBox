# 安装与使用

## 支持范围

设备：Raspberry Pi 4、约4GiB内存。宿主构建指纹：

```text
Raspberry/aosp_rpi4/rpi4:13/TQ3A.230901.001/eng.lijiaq.20260916.141216:userdebug/test-keys
```

需要宿主已有 MagiskSU、Permissive、User/Mount/PID/Network/IPC/UTS/Cgroup namespace、OverlayFS、binderfs、混合 cgroup 控制器、对应 Mesa/GPU 驱动和已联网的 wlan0。0.1.3必须能创建User namespace，没有Host UID0回退。App 会检查这些条件，并自动将已校验 BusyBox 安装到新项目私有工具目录，不需要修改宿主 system。Root 授权不能弥补内核或驱动缺失。

导入时会在 App 私有目录解压，再复制到 root ROM 库。带 Google 的当前包解压约2.5GiB，建议至少保留8GiB磁盘余量，选择的压缩包另计。前台通知显示进度，离开界面不会取消服务；不要强制停止 App 或断电。

## 首次运行

1. 在树莓派安装 `out/IrisBox-0.1.3.apk`。它有独立签名和包名，不覆盖旧 Iris。
2. 打开虹膜空间，在正常 Magisk 提示中允许 root。拒绝后可在宿主 Magisk 中重新允许，再点“授权与检查”。通知授权用于展示安装/导入进度。
3. 点“授权与检查”，确认宿主检查通过；点“安装内置引擎”。引擎来自 APK 内的校验包，不从旧项目目录安装。
4. 点“导入 ROM”，通过系统文件选择器进入“下载 / RootVMOS”，选择 `IrisBox-rpi4-a13-aosp.irisrom`，确认导入。也可选择 U盘/其他文档提供者上的同格式包。
5. 导入成功后点“管理实例”，再点“新增实例”。Google 和实例 Magisk 是可选项；宿主授权与实例 root 开关是两件事。
6. 点击“启动”，等本次日志显示桌面就绪，再“进入”。列表提供低频预览，全屏使用独立图形缓冲区管线。
7. 双开时再新增第二个实例。每个实例各有应用、账号、数据和配置；更多卡片不表示物理内存可以支持无限并发。

从0.1.2/e13保留实例升级前，先阅读[停机备份与User namespace迁移](09_User_namespace隔离与迁移.md)。仅安装新APK不能迁移旧属主元数据。768MiB保留实例本轮首次映射启动约175秒，1536MiB Google实例约78秒，应等待就绪后再进入。

Google账号保留不等于设备认证。每个实例的GSF ID独立；登记过宿主或旧项目不代表新实例已登记。出现未认证提示时，按[Google自定义ROM官方登记页](https://www.google.com/android/uncertified/)使用当前实例自己的GSF ID，由本人登录并完成验证码。不要公开号码，也不要反复清空GSF来换号。登记不等于厂商认证或Play Integrity通过，当前商店限制见06验收记录。

新建普通实例内存默认1.25GiB，带Google的新实例默认1.5GiB，上限可在停止后调整为0.5～2.5GiB。启动前按配置预算加余量检查 MemAvailable；不足时拒绝本次启动，不停止已有实例。0.5GiB仅是可配置下限，本次空白实例冷启动在该预算下失败；不带Google的两实例已分别用768MiB、1024MiB验证，带Google及Magisk的临时实例用1280MiB验证。登录Google并运行Chrome的实例2曾在1280MiB下频繁触及限制，已调为1536MiB；新默认值以此为依据。这台4GiB宿主建议先启动带Google的实例2，再启动普通实例1；普通实例先运行时MemAvailable曾不足Google实例启动预算而正常拒绝。该保护保留，不抢停已有实例。实际应用负载需要另外留余量，旧项目也在运行时共同占用同一块物理内存。

## 日常操作

退出 App 不会停止实例；重新打开后，进入管理页可经正常 root 恢复本项目后台。宿主重启后先打开 App，再点启动；不依赖电脑部署，也不配置宿主 init 自动启动实例。

分辨率、内存、Root 设置停止后修改。文件页沿用旧项目的 Android MediaProvider 导入/导出。日志按每次启动保存，停止卡片默认未启动，通过“上次日志”查看历史。

导入另一个 ROM 只改变随后新建实例的默认 ROM，已有实例继续使用原 ROM ID。同一个 ID、相同清单允许重复导入；同 ID 不同内容拒绝覆盖。当前没有 ROM 删除和实例跨 ROM 迁移界面。

“重置”清空选定实例的数据，“删除”移除该实例；都需要原有版本/编号确认。不要用这些操作修复宿主授权或 ROM 文件问题。

## 失败处理

文件损坏、路径越界、文件摘要不符、缺少适配材料会在导入阶段拒绝，ROM 不会登记。可重新选择完整包。App 暂存文件正常退出时自动清理；中断后的恢复见维护文档。

新实例启动失败时先保存本次日志，不清空旧项目数据。不支持的指纹、SELinux、GPU 或网络条件应由对应适配解决；不要把 `su` 成功当成兼容证据。

## 公开发行

公开包不含 Google。现有私人 Google 实例保持原 ROM、数据和登录。语言切换、干净宿主镜像、下载与验证边界见[国际化与发布](08_国际化与发布.md)。
