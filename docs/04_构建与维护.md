## 2. 本机完整构建流程

### 工具链要求
- **JDK**：JDK 17（如 Eclipse Adoptium 17）
- **Android SDK / NDK**：Android SDK Platform `android-30`（编译接口基线，APK `targetSdkVersion` 为 `33`）、`build-tools 34.0.0`、NDK `28.2.13676358`
- **脚本环境**：PowerShell + Python 3

### 构建命令

```powershell
# 完整构建（编译内置浏览器、Native 助手、Java 服务、封装 engine.zip 并签名 APK）
./build.ps1 -SdkDir "$env:LOCALAPPDATA/Android/Sdk" -JdkDir 'C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot'

# 仅修改宿主 App UI（确认内置引擎未发生任何改动时，复用已有 engine.zip 与 profile）
./build.ps1 -AppOnly -SdkDir "$env:LOCALAPPDATA/Android/Sdk" -JdkDir 'C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot'
```

### 构建管线步骤与版本纪律
1. **构建流水线**：生成中英文国际化资源与状态字典 → 编译普通实例下载浏览器（`app/guest-browser`） → NDK 编译 `irisbox_ns` / `irisbox_userns` 与联网 BPF helper → `javac` / `D8` 编译 `AudioBridge`、`BufferBroker`、`BufferGateway` → 规范化 JAR 时间戳并生成引擎清单 → 封装 `engine.zip` 并生成 `rom-profile.json` → 编译 Viewer JNI 与 Java 源码 → `aapt` 打包资源与资产 → `zipalign` → 使用项目独立密钥签名并通过 `apksigner` 验证 → 输出 `out/IrisBox-0.1.6.apk`。
2. **引擎版本纪律**：只要修改了控制脚本、`Broker`、`Gateway`、内置浏览器或 Native helper，**必须递增引擎版本号并执行完整构建**。严禁在相同引擎版本号下发布不同内容（安装器会拒绝摘要不匹配的同版本覆盖）。
3. **双签名密钥管理**：
   - 宿主 Viewer 测试密钥位于本地忽略的 `app/viewer/build/viewer-test.keystore`。
   - 实例下载浏览器（`0.1.4+`）使用独立的私有密钥 `app/guest-browser/build/browser-test.keystore`。
   - 两份私钥均不提交、不公开，且本机必须妥善保留以支持后续覆盖安装更新（切勿复制旧参考工程密钥）。公开源码克隆构建时会生成新的本地开发密钥，因此复核公开源码构建一致性时，应**比对全部非浏览器引擎载荷的 SHA-256 摘要，以及浏览器 APK 内部的未签名 ZIP 条目**（详见 [实例内下载浏览器说明](../app/guest-browser/README.md)）。

## 3. 源码与预编译材料边界

- **本机直接重编部分**：`app/`（Viewer、Broker、Gateway、Guest Browser）与 `engine/` 下的控制器、音频桥、UserNS 启动器、网络 helper 均由本仓库源码直接编译。
- **固定 AOSP 13 兼容载荷**：ROM 中的 `iris_init`、no-BPF 网络库、Connectivity 兼容库、Mesa/Gralloc、DocumentsUI、输入/文件客户端及闹钟 JNI（`libalarm_jni.so`，补丁与摘要见 `reference/patches/userns-alarm.patch` 与 `reference/userns-provenance.json`）复用经过核验的匹配 AOSP 13 构建产物，其补丁与来源索引保存在 `reference/` 下。构建宿主 APK **不等于从零全量重编整个 AOSP**。
- **图形 Producer 独立远程重编（可选）**：
  `engine/native/buffer/` 保存了图形 `buffer_producer.cpp` 源码与直接编译脚本（修复了单帧预览在 Binder 线程活跃时触发 C++ 进程退出静态析构竞争的问题，在释放 buffer 后直接调用 `_exit`）。如需在匹配的 AOSP 编译机上重编，可传入您自己的编译机参数（公开版本不内置任何私人编译机地址或密钥）：
  ```powershell
  ./build.ps1 -RebuildProducer `
    -ProducerHost builder@YOUR_HOST `
    -ProducerKey C:/path/to/id_ed25519 `
    -AospDir /path/to/aosp-rpi4
  ```
  该脚本仅在远程 `/tmp/irisbox-producer-UUID` 临时目录中编译并回传 ARM64 ELF 二进制，保持远程 AOSP 源码树只读。
- **一次性初始提取脚本禁令**：`tools/extract_reference.py` 与 `tools/adapt_engine.py` 仅用于记录项目最初从参考工程提取与转换的方法，**日常开发严禁再次运行以免覆盖当前维护源码**。

## 4. 开发期引擎事务升级与故障恢复

当前 App 界面尚不提供跨版本引擎自动升级按钮；开发与维护升级统一使用 `tools/upgrade_engine.py`（所有 Android `.sh` / `.rc` 脚本必须保持 `LF` 换行，打包器会拒绝 `CR` 字节，且升级提交前会在设备上逐个执行 `sh -n` 语法检查）：

```powershell
# 1. 先在 App 中正常停止所有实例，保留当前已安装版本对应的旧 APK
# 2. 执行核验与事务性引擎升级（以 0.1.5 -> 0.1.6 为例）
python tools/upgrade_engine.py --from-apk out/IrisBox-0.1.5.apk --apply

# 3. 若升级过程中断留下 engine-upgrade.pending 标志（此时 App 会拒绝拉起后台），可执行独立恢复：
python tools/upgrade_engine.py --recover
```

- **事务保障**：升级工具会先核对设备当前引擎清单与旧 APK 完全一致，创建独立备份后仅替换固定引擎文件，不覆盖 ROM、配置或实例 `upper` / `data`（注意：引擎文件备份不是用户 `data` 备份）。
- **切根路径纪律**：实例在 `pivot_root` 前其 `/product` 为指向宿主的绝对软链接，因此任何预装至实例的载荷必须使用实例私有根下的物理路径 `rootfs/system/product/...`。

## 5. 设备核验工具与彻底卸载流程

### 开发者设备核验 CLI（`tools/device.py`）
- 设置环境变量 `IRISBOX_SERIAL` 指定您的 ADB 设备序列号。
- `python tools/device.py preflight`：只读检查宿主环境。
- `python tools/device.py state`：查询 `19762` 端口实例状态（自动隐去认证令牌）。
- `python tools/device.py baseline` / `compare --old-stopped [--host-rebooted]`：校验旧参考工程脚本、注册表、配置与身份记录未被改动。`device.py` 对调试 `su` 采用显式 `EXIT` 状态码标记，防止设备 `su` 包装器吞掉子命令错误码。

### 恢复与彻底卸载步骤
- **保留数据重装**：直接卸载宿主 APK **不会清除 `/data/irisbox`**，旨在保护用户的实例与账号数据；重新安装相同签名的 APK 即可恢复管理入口。
- **彻底卸载清理顺序**：
  1. 若启用了宿主交换空间，先在 App“交换空间”页将其设为 **“关闭”** 并取消自动恢复，等待停用完成。
  2. 在 App 内逐个**停止并删除**所有虹膜空间实例，随后停止本项目 `manager`。
  3. 核验 `irisbox_*` 资源组为空、网络账本已回收、所有 `rom` 只读 loop 挂载已解除后，再删除已解析且确认为 `/data/irisbox` 的目录。
  4. **严禁操作**：切勿删除 `/data/guest`（旧参考工程目录），切勿全局卸载共享 BPF 分派器、清空宿主 `iptables` 或通过盲目递归删除整个运行目录来处理单次导入中断（导入中断遗留的 `.rom-UUID` / `.engine-UUID` 应在确认无进程写入且无子挂载后单独清理）。
