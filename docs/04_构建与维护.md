# 构建、恢复与维护

## 本机构建

已使用JDK17、Android SDK platform android-30、build-tools34.0.0、NDK28.2.13676358和Python3。APK目标API33，SDK30仅是当前编译接口基线。路径可通过参数覆盖。

```powershell
./build.ps1 -SdkDir "$env:LOCALAPPDATA/Android/Sdk" -JdkDir 'C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot'
```

构建顺序：NDK编译namespace helper与联网helper → javac/D8编译AudioBridge、Broker、Gateway → 规范JAR时间并生成引擎完整清单 → ZIP封装引擎、生成ROM兼容profile → 编译Viewer JNI及Java → aapt打包资源/资产 → zipalign → 本项目独立测试密钥签名 → apksigner验证 → 输出APK。

只修改UI、确认引擎不变时可加`-AppOnly`，复用已生成的engine.zip/profile。修改控制脚本、Broker或native helper必须完整构建。不要在相同引擎版本下发布不同内容；安装器会拒绝摘要不同的同版覆盖。发布前增加引擎版本，并实现/验证对应升级事务，本版尚不支持自动升级已安装的不同引擎。

测试密钥在新项目`app/viewer/build/viewer-test.keystore`，不提交、不公开。保留密钥才能覆盖安装更新。不要复制旧项目密钥，或在已有实例中随意换签名。

## 哪些是源码，哪些是预编译材料

`app/`和`engine/`的控制器可本地重编。ROM的init、no-BPF、Connectivity、Mesa/Gralloc、DocumentsUI等复用旧项目固定AOSP13构建产物；补丁和输入来源保存在`reference/`。图形producer已有本项目源码和独立AOSP编译入口；Guest输入/文件客户端的固定配套二进制继续复用。整套系统组件从空白AOSP源码完整重建未在本次完成，不能把本地APK构建称为全量Android重建。

`tools/extract_reference.py`和`adapt_engine.py`仅记录首次提取/迁移方法，运行会重新生成初始材料；正常开发不要重新执行覆盖当前源码。初始参考本地目录含未提交改动，以`reference/source-inputs.json`的逐文件来源与摘要为准，不仅凭旧Git提交号归因。

## 设备核验

`tools/device.py preflight`只读检查宿主；`baseline/compare`保存并对照旧脚本、注册表、内存/分辨率配置、活跃init身份、Host boot_id和socket策略。`state`查询新端口，不输出认证令牌。原始现场材料位于忽略的`validation/private/`，不要公开账号、屏幕或完整设备日志。

用户随后授权正常关闭旧项目且不恢复，本轮使用`compare --old-stopped`核验旧文件不变。真实宿主重启后的核验增加`--host-rebooted`：要求boot_id改变、旧实例未运行、旧配置及身份记录不变；不要求重启后内核对象数字ID相同。不要将这些选项用于掩盖未经授权的状态变化。

使用正常App流程安装引擎和导入；开发者CLI只用于复核状态、执行受控测试。`tools/ui.py`读取真实可见文本与bounds，再操作该节点；不猜测点击位置。

## 恢复与卸载

卸载APK不会自动清除`/data/rootvmos`，目的是保留实例数据。重新安装相同签名APK可恢复入口。需要彻底删除时：先在新App逐个停止和删除新实例，再停本项目manager；核验本项目资源组为空、新实例网络账本已回收、新ROM lower挂载/loop已解除后，才可删除已解析且确认属于`/data/rootvmos`的目录。不要删除`/data/guest`，不要全局卸载BPF、清空iptables或重启宿主来卸载新App。

导入失败只会留下未登记的暂存目录。正常异常退出清理App的对应package-work目录；进程被杀或断电时可能留下旧work、`.rom-UUID`或`.engine-UUID`。先确认没有SetupService或安装进程在写入，且路径位于`/data/rootvmos`或本App私有package-work内、不是链接、没有子挂载，再单独清理该临时目录。不要递归删除整个运行目录来重试。

首装在移动引擎后、初始化注册表前中断时，可经本项目`instances.sh init`完成登记；该命令不会创建默认实例。引擎已安装后重复安装同摘要为幂等检查，不覆盖config/instances。自动升级、ROM删除、完整数据迁移和一键彻底卸载属于后续工作。

## 预览助手独立重编

`engine/native/buffer/`保存producer源码和直接编译脚本。`build.ps1 -RebuildProducer`会调用`tools/build_producer.py`，使用已获用户授权的AOSP编译机AOSP_BUILD_HOST。仅发送本项目producer源码、构建脚本和缓存的编译参数，在独立`/tmp/rootvmos-producer-UUID`生成对象及二进制；AOSP树、旧工程及输出库均只读。SSH私钥仅本地使用，不上传；不发送ROM、账号或实例data。

需要设备匹配的AOSP私有头文件、已有screencap编译参数和共享库，不能用公开SDK代替。编译后回传ARM64 ELF，验证摘要，更新新项目载荷与`reference/producer-build.json`。本轮修复的是单帧预览在Binder线程运行时触发C++进程退出析构竞争；正常buffer释放后直接`_exit`，全屏流管线保持原有引用与fence释放协议。

## 保留数据的开发维护升级

0.1.1/e9提供`tools/upgrade_engine.py`开发维护工具，App尚无自动跨版升级界面。先正常停止所有新Guest，保留当前安装版本对应APK；例如e8到e9：

```powershell
python tools/upgrade_engine.py --from-apk out/qa/RootVMOS-0.1.1-e8.apk --apply
```

工具核验旧APK与设备engine清单及每项摘要，建立独立备份，只更新新APK中固定引擎文件，最后提交版本/摘要。ROM、配置、实例upper/data不迁移、不覆盖。存在`engine-upgrade.pending`时App拒绝拉起后台；失败会尝试回滚，仍中断时使用`python tools/upgrade_engine.py --recover`运行该待处理目录中的恢复脚本。备份保留，不能将其当作用户data备份；没有模拟突然掉电验证。

`tools/device.py`对调试su使用显式EXIT状态标记，因为该设备su包装器可在子命令失败后仍返回ADB退出码0。成功必须同时满足命令退出状态和最终提交点，不能只看传输成功。

打包器拒绝Android `.sh/.rc` 中的CR字节；维护升级在提交前逐个执行设备`sh -n`。Git属性保留LF，但打包器不依赖尚未提交的工作区自动转换。Guest切根前的`/product`是绝对链接，新增载荷必须使用私有rootfs下的`system/product`物理路径。
