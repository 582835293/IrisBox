# 0.1.5：Iris 命名空间与设备目录迁移指南

**简体中文** · [English](en/namespace-migration.md) · [返回主页](../README.zh-CN.md)

---

## 1. 迁移范围与核心原则

`v0.1.5 / e25` 将产品自身的宿主应用包名、设备运行根目录、内置下载浏览器、原生启动器、音频服务、抽象套接字与 cgroup 资源组全面统一为 **IrisBox（Iris）** 命名：

- **新宿主包名**：`com.irisbox.viewer`（内置实例浏览器同步更新为 `com.irisbox.browser`）
- **新设备根目录**：`/data/irisbox`（运行根 `/data/irisbox/runtime`）
- **保持不变项**：管理端口 `19762`、实例编号、数据 `revision`、User Namespace UID/GID 映射范围（`2000000000+`）、ROM 绑定及所有第三方应用/游戏数据与 Google 账号状态。
- **唯一共享例外**：宿主全局 BPF 网络分派器（`/sys/fs/bpf/iris_inet_v1`）经身份核验后继续安全复用，不迁移、不抢占、也不删除其他项目的网络权限表。

> [!WARNING]
> **存量 `0.1.4 / e21` 用户必读**
> - **不可直接覆盖安装 APK**：由于宿主包名变更为 `com.irisbox.viewer`，Android 系统将其视为全新应用。存量 `0.1.4 / e21` 安装必须先执行下方的**停机迁移事务**，并在安装新 APK 后通过宿主 Magisk 正常授予新包 Root 权限。
> - **三不原则**：切勿手工复制 Magisk 授权数据库，切勿清空 Google 服务数据，切勿通过删除重建实例来升级（全新安装用户无需执行本迁移，直接按 [安装与使用指南](01_安装与使用.md) 操作即可）。

## 2. 维护者停机迁移步骤（`0.1.4 / e21 → 0.1.5 / e25`）

本迁移工具（`tools/migrate_namespace.py`）仅支持经过严格摘要核验的 **`0.1.4 / e21 → 0.1.5 / e25`** 停机迁移。执行前请确保保留已安装的旧版 `IrisBox-0.1.4.apk`、对应签名密钥以及充足的磁盘备份空间（旧参考工程仅作只读参考，严禁将其目录作为迁移源）：

1. **正常停止全部实例**：
   在旧版 App 中正常停止所有实例，等待显示、网络、挂载及后台任务彻底清理完毕，随后关闭旧版 App 界面以防后台重连。
2. **连接设备并执行预检**：
   设置环境变量 `IRISBOX_SERIAL` 指定您的 ADB 设备。迁移工具会从传入的旧 APK 中读取原包名与原设备根目录，并严格校验设备上已安装 APK 的字节摘要、引擎全文件 SHA-256、`PID:start_tick`、空 cgroup 资源组、网络账本归属及只读 `lower` 挂载。任何一项不匹配均会立即中止。
3. **先执行只读检查，再附加 `--apply` 提交迁移**：
   ```powershell
   # 第一步：只读预检（不修改设备状态）
   python tools/migrate_namespace.py `
     --from-apk out/IrisBox-0.1.4.apk `
     --to-apk out/IrisBox-0.1.5.apk

   # 第二步：执行停机完整备份与目录/引擎原子迁移
   python tools/migrate_namespace.py `
     --from-apk out/IrisBox-0.1.4.apk `
     --to-apk out/IrisBox-0.1.5.apk `
     --apply
   ```
4. **工具内部执行的停机事务**：
   - 为每个实例的 `data`、`upper`、`vendor.upper` 与 `metadata` 创建**独立 inode 的完整副本**（非硬链接），逐文件核对源与副本的 SHA-256 摘要，并保存配置文件与旧引擎回退材料。
   - 安全释放经核验归属本产品的只读 `lower` 挂载，停用旧入口，安装新版本可信引擎，并将产品根目录整体迁移至 `/data/irisbox`（旧显示指针与旧音频临时文件保留在事务备份中，不再复用其中的旧绝对路径）。
5. **安装新 APK 并重新授予宿主 Root**：
   安装 `IrisBox-0.1.5.apk`（或后续同签名的 `0.1.6` APK），打开应用点击 **“1 · 授权与检查”**，在宿主 Magisk 弹窗中允许新包授权，检查通过后进入管理页启动原有实例。迁移工具不会自动卸载旧 APK；请在确认实例数据、账号、显示、输入、网络及隔离均正常后，再备份并卸载旧入口应用。

### 收据与内置浏览器变更说明
- **私有迁移收据**：迁移记录保存在本地忽略的 `out/maintenance/namespace-transition.json` 中，设备端备份随产品根目录位于 `/data/irisbox/maintenance/` 下（**注意：同盘备份不能替代外部独立磁盘备份，且切勿公开收据、账号指纹或原始日志**）。
- **内置浏览器包名变更影响**：内置下载浏览器包名同步更新为 `com.irisbox.browser`，因此旧浏览器私有缓存与 `DownloadManager` 历史记录不会自动映射为新 UID 的下载列表（原已下载的文件与旧状态完整保存在迁移快照中）；而 Google、游戏等第三方应用的包名与 UID 布局保持完全不变。

## 3. 异常处理与事务回退规范

- **存在 `engine-upgrade.pending` 时严禁强行启动**：若迁移中途异常中断并留下 `engine-upgrade.pending` 标志，请先保留收据与终端错误输出，确认所有实例与显示进程处于停止状态，并检查收据中记录的 `recover.sh`（切勿盲目手动删除标志文件、递归修改属主或重跑初始提取脚本）。
- **自动回退机制验证**：在执行阶段若发生错误，事务会自动调用原引擎与原路径回退。实机测试中曾捕获一次源脚本短变量名覆盖事务目标变量的情况，自动回退机制成功保护了全部实例数据；改为专用事务变量并增加子 Shell 隔离检查后重新迁移一次通过。
- **回退脚本的适用边界**：生成的 `recover.sh` 仅针对**当次停机目录/引擎迁移事务**。若维护者已卸载旧入口 APK，需先重新安装**完全相同的一份旧 APK** 才能恢复其入口与正常授权；若迁移完成后新实例已经启动并产生了新的写入数据，切勿盲目用旧快照直接覆盖，也绝不能将旧引擎强行套用在不匹配的目录属主布局上。

## 4. 已验证结果摘要

本轮实机成功迁移两个存量实例，实例 ID、数据 `revision` 与 User Namespace UID/GID 映射范围完整保持；实例 2 的 Google 账号私有 HMAC 指纹与 GSF ID 不变，重启后可继续从 Google Play 商店下载安装应用。新包名正常取得宿主 Magisk 授权，中英文切换与全屏游戏交互全部通过（详细应用测试结果与未通过的设备认证边界见 [实机验收记录](06_验收记录.md)）。
