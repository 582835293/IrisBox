# 2026-10-15 实机验收记录

本记录区分本项目新建环境的实际结果与旧项目历史能力。设备为树莓派4 / 固定AOSP13 / 约4GiB内存。旧Iris实例7在本轮开始时运行，其余旧实例8、23没有活跃init。测试起初保留旧实例运行；随后用户明确回复“直接关闭之前的吧，也不用恢复了。暂时用不到了”，据此正常停止旧实例7及旧后台，保留数据与配置，不再恢复旧项目。没有复制旧账号或旧实例data。

## 已完成的安装与静态检查

- 独立APK包名、签名、API33目标版本；安装没有覆盖旧Iris。继承的API30目标版本曾被系统拦截，已调整为API33，通过正常安装完成，未关闭安装保护。
- App经宿主Magisk正常授权，拒绝时可见失败提示；随后通过Magisk仅开启RootVMOS开关。旧Iris授权保持。
- App内宿主检查、内置引擎首次安装、系统文件选择器返回文档URI、解压/摘要校验、root ROM库提交均已实际完成。
- 生产PackageArchive在Android上执行11项测试全部通过：正常包、坏SHA、缺文件、重复项、未声明项、超出声明大小、错误profile、路径穿越、绝对路径、错误首项和超大清单。
- 本地与设备引擎39项摘要、Shell语法、116项ROM适配profile、54项Google静态文件、11项Magisk组件通过核验；e2原生助手已实际执行new-cgroup并正常退出。
- 旧本地52项当前源码输入与提取时摘要一致；关闭旧项目以前，设备旧脚本/注册表/内存/分辨率配置、活跃init PID:start_tick、Host boot_id和根socket策略在多次对照中保持一致。授权关闭以后，旧文件和身份记录继续保持，正常停止回收旧实例网络。宿主重启会重建内核对象，不以BPF数字ID不变作为重启后要求。

## 遇到并保留的失败

1. Google原始清单含特定换行字节，初次提取格式化改变了摘要。组件审计在导入前发现，恢复原始字节并重新打包；Git attributes为固定组件禁用自动文本转换，54项审计通过。
2. e1首次新实例启动在创建Guest前返回3：脚本调用rootvmos_ns，包内文件仍叫iris_runtime_ns。统一二进制打包/安装名称为rootvmos_ns，新增文件名与ARM64检查，升级为e2。e1本轮测试安装在停止本项目后台、确认无Guest/init/网络/挂载后归档至`/data/rootvmos/qa-e1-20261015`；ROM与测试设置保留。旧Iris没有迁移或覆盖。
3. e2重新从APK安装并再次走系统文件选择器导入，同一ROM包继续校验并成功启动。
4. 512MiB的新实例冷启动触及内存限制，未进入桌面。正常停止该新实例，调至768MiB后成功；因此不能将可配置下限512MiB宣称为推荐可用内存。
5. 文件交换测试连续提交操作时曾收到423：上次HTTP下载刚结束，但后台仍在释放操作锁。测试改为有限次数等待后重试，最终逐字节及摘要对照通过；没有绕过锁。

### 真实宿主重启

停止全部新Guest并同步后正常重启树莓派。Host boot_id由`13a37c82-d769-436b-8c55-3751ea0691ab`变为`11e48d19-552f-4a85-bafc-5db16aa6d3a7`，宿主版本和Permissive保持。没有打开旧Iris，也没有从电脑重新部署引擎或ROM。直接打开新App进入管理页，后台自行恢复并保留两实例配置；App按钮启动1007，42,083ms进入桌面，启动1008，46,919ms进入桌面。初次测试等待上限45秒不足以覆盖后者，延长观察后就绪；产品没有报错。开发等待工具上限已调整为90秒。

两实例重启后的Probe仍为普通UID10084，计数分别保留1和2，HTTPS均返回200，列表两张预览持续更新。新联网助手`verify`通过分派器、原宿主程序和宿主map匹配校验。`compare --old-stopped --host-rebooted`通过：Host确已重启、旧Guest无活跃init、旧脚本/配置/注册表和身份记录不变。
