## 1. 整体调用拓扑

```mermaid
flowchart TD
  A[SetupActivity 首次配置] --> B[标准 MagiskSU mount-master]
  A --> C[SetupService 前台安装与导入]
  C --> D[PackageArchive 清单与逐文件摘要校验]
  D --> E[独立 root ROM 库]
  B --> F[本项目 manager.sh / BufferBroker]
  F --> G[instances.sh / ctl.sh]
  G --> H[wrapper / namespace helper / inner]
  H --> I[ROM 只读镜像与每实例 Overlay 和 data]
  I --> J[适配原厂 init second_stage]
  J --> K[Android 服务与 Launcher]
  K --> L[Producer / Gateway / Native Viewer]
```

### 核心运行机制
1. **受控特权入口**：宿主 APK 是普通 Android 应用，仅通过用户显式授予的宿主 Magisk Root 拉起受控后台。后台由 root `app_process` 运行 `BufferBroker`，在本地回环 `127.0.0.1:19762` 上提供基于随机 Bearer Token 的管理协议（`HTTP 202` 仅代表请求已受理，最终状态由状态轮询与真实 Guest 会话核验共同确定）。
2. **七类命名空间与只读共享底包**：ROM 的 `system.img` 与 `vendor.img` 通过只读 `loop` / `ext4` 挂载在实例间安全共享；每个实例拥有独立的 `system`/`vendor` Overlay（`upper` / `work`）、`data`、`metadata`、启动日志与配置文件。自 `0.1.3` 起，每个实例运行在独立的 **`user` / `mnt` / `pid` / `net` / `ipc` / `uts` / `cgroup`** 七类命名空间中；实例内 `root` 经 UID/GID 映射隔离，不再与宿主 `root` 同身份。容器直接共享宿主 Linux 内核与 ARM64 指令集，不模拟 CPU，也不引导 `boot.img`（详见 [User Namespace 隔离与数据迁移](09_User_namespace隔离与迁移.md)）。
3. **私有 BinderFS 与原厂 `init` 引导**：每个实例挂载独立的私有 `binderfs` 设备；根挂载树先设为 `make-rprivate` 再执行 `pivot_root`，严禁实例挂载全局 `fusectl` 或操作物理可移动存储介质。实例内部由经过适配的原厂 Android `init second_stage` 统一管理系统服务，而非通过 Shell 脚本逐个拉起服务。

## 3. 网络唯一共享点：根 cgroup Socket 分派器

Android 的根 cgroup `socket-create` BPF 策略属于宿主全局内核对象。若强行替换或抢占该分派器，将破坏宿主或旧工程的网络控制。为此，IrisBox 采用**核验后安全复用**策略：

- **兼容挂载与独立表注册**：联网助手兼容既有 `/sys/fs/bpf/iris_inet_v1` 协议——先严格校验原 BPF 程序、Host UID Map、`domains` Map 及当前挂接身份，确认无误后仅向同一 `domains` Map 中写入本项目实例的 **`netns cookie → 私有 UID Map`** 映射。宿主权限表保持原样，各实例原厂 `PermissionMonitor` 仅维护实例自己的权限表。
- **不抢占、不恢复、不越界清理**：
  - 若检测到旧分派器已存在但挂接身份异常，直接拒绝操作。
  - 新联网助手**不提供 `restore` 子命令**，允许登记或移除的实例 ID 严格限定在 `1007`～`1134`。
  - 移除实例网络表时强制校验 `netns cookie` 与 `map ID` 双重匹配；停止实例时**绝不卸载共享分派器、不删除旧项目 Guest 表、也不清空（flush）宿主防火墙规则**。
- **空白宿主边界**：在从未运行过旧项目的全新受支持宿主上首次启动时，引擎会校验原厂策略并初始化该分派器；但该全新宿主路径需在空白刷机盘上另行实测，不能由现有设备的共存测试直接推断。

## 4. 安装、ROM 导入与生命周期事务

1. **严格的归档解包校验**：所有控制脚本均由已签名的宿主 APK 提供。导入 `.irisrom` 时强制校验：ZIP 首项必须为 `rom.json` 清单，文件名符合 ASCII 白名单，且总大小、单文件大小、重复条目、未声明文件、缺失文件与逐文件 SHA-256 摘要全部匹配。解包过程仅创建普通文件，拒绝任何符号链接、特殊权限或归档内脚本执行。
2. **双阶段 ROM 入库与兼容 Profile 锁定**：ROM 必须匹配目标 ABI、Android API 级别、宿主构建指纹与适配 Profile，`system.img` / `vendor.img` 必须具备合法的 raw `ext4` 魔数，且关键 `compat/` 载荷摘要须与 APK 内置的 `rom-profile.json` 逐项一致。App 侧校验通过后复制到 root 暂存目录二次复核摘要、设置权限与 SELinux 标签，`sync` 后原子移动为正式 ROM ID 并更新新建实例默认 ROM（拒绝覆盖同 ID 但内容不同的 ROM）。
3. **版本与会话身份防重放**：每个实例通过 `config/rom_v1/ID.id` 永久绑定创建时的 ROM 版本；`revision` 标识数据目录代次，`session = PID:start_tick` 标识内核进程运行代次，两者严格区分、不可互换。停止、重置与删除操作均强制执行身份核验、生命周期锁、挂载归属及 cgroup 检查。

## 5. 音频、视频与系统服务适配

### 虚拟音频回环与宿主混音（单向播放）
- **架构设计**：实例使用 ROM 自带的 `default` 虚拟音频 HAL，不映射宿主 `/dev/snd`，也不修改宿主音频配置。实例启动完成后由 Guest `init` 拉起 `irisbox_audio`：通过 `AudioPolicy` 的 `LOOP_BACK` 捕获媒体播放流，以 `48 kHz / 16-bit / 双声道 PCM` 格式经权限为 `0700` 目录 / `0600` 文件的受保护 Socket 发送至宿主。宿主端为每个实例维护一个独立的 `AudioTrack` 播放进程，由宿主 Android 音频系统完成多实例混音（仅支持实例声音播放，不含麦克风录音路径）。
- **会话绑定与故障自愈**：宿主播放器与监督脚本严格绑定实例的 `PID:start_tick` 及随机令牌。一旦连接断开，宿主端立即释放 `AudioTrack` 并显式终止 Java 进程，监督脚本自动重建连接，无需重启实例主会话。管理接口中的 `audio.ready` 反映会话、播放器身份与采样进度正常，不等同于物理扬声器人耳听感确认。

### 软件视频解码与 `Traceur` 屏蔽
- **媒体解封装与软解恢复**：通过存放在实例 `product` init 目录下的 `zzz_irisbox_media.rc` 恢复被精简 ROM 禁用的系统标准 `mediaextractor` 解封装服务，并保留原厂 `mediaserver` 与软件 Codec。实例私有 `vendor` 编解码配置从 ROM 原始清单生成并剔除不可用的 `V4L2` 硬件解码项（不向实例暴露宿主 `/dev/video*`），由软件解码器承载 MP4 / H.264 视频播放（不涵盖 DRM 受保护视频）。
- **私有挂载屏蔽 `Traceur`**：原厂 ROM 中的系统应用 `Traceur` 依赖容器未提供的内核跟踪服务。在 Guest `init` 启动前，引擎仅在已确认为 `private` 的实例挂载命名空间内使用空 `tmpfs` 屏蔽 `rootfs/system/app/Traceur` 目录，既不删除只读 ROM 文件，也不影响宿主 APK。启动健康脚本仅以只读方式观察 `WindowManager` 就绪并标记 `READY`，不在 `system_server` 初始化阶段调用 `pm` 修改包状态，从而彻底消除启动竞态。

## 6. 官方规范与内核参考

- **[Android SELinux 安全架构](https://source.android.com/docs/security/features/selinux)**：说明强制访问控制（MAC）同样约束 `root` 进程；本预览版显式要求已配置好的 Permissive 宿主环境。
- **[Linux Kernel BinderFS 文档](https://docs.kernel.org/admin-guide/binderfs.html)**：说明不同 `binderfs` 实例的 Binder 设备节点相互独立。
- **[Android Storage Access Framework (SAF)](https://developer.android.com/training/data-storage/shared/documents-files)**：本项目通过系统文件选择器获取文档 URI 进行 ROM 导入与实例文件交换的标准依据。
